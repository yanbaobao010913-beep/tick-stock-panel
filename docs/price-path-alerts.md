# DSA 价格路径告警

DSA 托管点位规则原来采用 86400 秒冷却。上午到价后，下午即使发生深 V、反向收复、再次跌破，也可能没有新的告警。现在由显式 `price_path=true` 的路径状态机处理；旧人工规则缺省关闭此模式，保留原有冷却。

## 行为

| 情形 | 告警 |
| --- | --- |
| 第一次满足原方向阈值 | 立即触价提醒 |
| 持续处于同一触发区间 | 保持安静 |
| 从已观察低点反弹至少 3%，连续确认 60 秒 | 低位反弹观察，即使仍低于原阈值也提醒 |
| 越过原阈值的反向缓冲线，连续确认 60 秒 | 收复／回落提醒 |
| 确认收复后再次原方向穿越 | 再次触价提醒，不受旧全天冷却限制 |

缓冲为阈值的 0.5%，至少一个最小报价单位：股票 0.01、ETF 0.001。确认至少需要两条时间递增的新鲜快照。以上是工程去抖默认值，并非已经验证收益的交易策略。

例如 ETF 从 1.00 跌到 0.80，下午到达 0.824 后持续保持一分钟，会提示低位反弹；继续涨回关键线的缓冲外侧并确认，再提示收复。反弹观察和收复均为信息事件，自动跟单入口同时检查 `info_only` 和事件类型，禁止因此下单。原方向触价仍遵循原有跟单配置。

同一反弹段只报一次。价格比上一段低点再低至少 0.5%（至少一个报价单位），才允许形成新的反弹段。低点仅来自启用后的有效实时观测，不使用日线 high/low 推断盘中先后。

## 数据、风险和兼容

- 确认按北京时间 9:30–11:30、13:00–15:00 的交易秒数计算；午休保留状态和低点，不计入确认时间。
- 有时间戳的行情必须属于当日、处于连续竞价时间，距服务端当前时间不超过 180 秒且不能超前超过 5 秒。重复、倒序快照不推进确认；缺失、失效数据打断确认；相邻有效快照的交易时间间隔超过 180 秒也重新确认。
- 缺少时间戳的数据源仅兼容首次触价，不能产生收复或反弹确认。
- 同标的、同基础 kind、同事件类型的接近／逼近／到价，在记录、SSE、系统通知、Webhook、跟单之前统一保留最强一条；止损、买点、收复等不同事件分别保留。
- 买点或反弹时若仍低于主止损线，文案带风险提示。信息提醒不会替代止损。
- 当日状态持久化到 `data/user_data/price_path/state.json`，带版本、校验和，后台原子写入并合并待写快照，磁盘写入不持有行情状态锁。异常写入记日志并重试；进程被强制终止可能丢失尚未写完的最新状态。
- 同配置 reload 保留状态；改价、改方向、改 kind、停用、删除清理相关状态与低点；跨日重置。损坏状态文件保守重新开始，不凭空恢复历史低点。
- DSA 下次对账给旧托管规则补上模式和 kind，保留用户的 enabled 和 Webhook 渠道配置。旧客户端编辑保存时省略新字段，API 保留已有模式。

模式仅支持股票／ETF 的单标的、单条件 `close <=/>= 正有限数值` 规则，其余形状明确拒绝。部署后不能补报部署前未观测到的完整深 V 路径。回滚代码后，旧引擎仍按原冷却字段运行；新增状态文件不改变原告警历史或持仓。

## 验证

`test_price_path_monitor.py` 覆盖深 V、未收复反弹、再次穿越、单边走势、阈值抖动、股票／ETF tick、午休、断流、重启、配置变更。`test_price_path_merge_paper.py` 覆盖统一告警出口、信息事件禁止跟单、API 兼容；`test_price_path_boundaries.py` 补充陈旧首报、缺失数据、删除并发、坏文件和异步写盘回归。
